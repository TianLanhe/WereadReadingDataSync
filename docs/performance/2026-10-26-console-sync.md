# 同步整体耗时对照

## 测量边界

这是运行真实同步编排、数据转换、差异计算、封面调度及批量写入代码的受控 HTTP 模拟。未对真实飞书表格执行写入，也未把线上第二次无变化同步与第一次有变化同步比较。结果不代表生产网络的固定耗时或所有同步场景的加速比例。

- 机器：Apple M1 Pro，darwin/arm64，Go 1.26.4。
- 输入：30 本已有书籍（均有附件且评分变化，其中 1 本阅读时长变化），另新增 1 本；5 年每日阅读数据各 1 条，目标阅读表为空。
- 每个 HTTP 请求固定等待 40ms；已有 token 有效；所有 HTTP 请求被测试传输层截获，无法访问真实服务。
- 每次运行使用同一份原始两端数据，写入响应不会改变下一次运行的输入。
- 两版均将控制台输出丢弃，避免旧版整批 JSON 与新版终端渲染的输出设备差异干扰比较；终端展示另外验证。
- 各三次完整同步，以中位数作为比较值。

## 原版

| 次数 | 整体耗时 | HTTP 请求 | 上传封面 |
| --- | ---: | ---: | ---: |
| 1 | 5.966506s | 105 | 31 |
| 2 | 5.963763s | 105 | 31 |
| 3 | 5.965611s | 105 | 31 |

中位数：5.965611s。

## 优化版

| 次数 | 整体耗时 | HTTP 请求 | 上传封面 |
| --- | ---: | ---: | ---: |
| 1 | 0.507709s | 45 | 1 |
| 2 | 0.505842s | 45 | 1 |
| 3 | 0.503355s | 45 | 1 |

中位数：0.505842s。整体耗时从 **5.965611s 降到 0.505842s**，减少 **91.52%**，约为原来的 **1/11.79**。

优化版测量包括 ConsoleReporter 的普通文本格式化、排序和评分过滤，输出同样写入 `/dev/null`；动态光标刷新通过真实 PTY 单独验证。

连接池另用真实本地 HTTP 服务验证：两轮各 10 个并发请求，旧默认池建立 18 条连接，优化池复用后共 10 条。此项不混入固定延迟的 HTTP 模拟耗时。

## 原因与适用范围

原版只要任何书籍字段变化就重传封面，评分变化也会产生图片下载和素材上传。优化版保留已有附件，只有新增或缺附件时才上传。本夹具因此减少 30 次下载和 30 次上传。另将独立读取改为有界并发、日期比对改为索引查找、封面轮询改为完成通知，并移除为日志进行的整批序列化。

新书很多、附件大量缺失、真实接口较慢、触发限流或登录需要扫码的场景仍受网络和服务上限影响；不能把本结果泛化为始终相同比例提速。上传间隔采用严格匀速而不依赖初始突发额度。

## 复现

```bash
WEREAD_RUN_LIVE_TESTS=0 WEREAD_RUN_LIVE_MUTATION_TESTS=0 \
  go test -run '^$' -bench '^BenchmarkSyncScenario$' -benchtime=1x -count=3
```

夹具位于 `sync_benchmark_test.go`，原版结果是在修改生产代码前运行该夹具取得。单元测试套件运行时间、Go 编译时间均不是本表的同步耗时。
