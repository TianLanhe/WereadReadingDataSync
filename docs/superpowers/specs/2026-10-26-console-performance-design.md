# 控制台展示与同步性能设计

用户已在对话中确认本设计，并要求最终报告同条件下整体耗时前后对比。

## 目标与约束
- 单套输出：保留历史变更，底部局部动态进度；非终端降级为普通文本；不增加 verbose。
- 除评分外所有已比较字段的变更均显示旧值和新值，新增删除全部列出，不限条数。仅评分变化只汇总，评分继续同步。
- 结构化差异、进度事件与终端渲染分离；不在业务函数中拼日志；错误只完整报告一次。
- 现有附件保留，仅新增或附件为空时上传；不因普通字段变化重新上传。现有附件不会自动跟随远端换图。
- 上传请求间隔 205ms，最多 5 个并发，每次尝试均受同一限速器约束；初次加最多两次重试；限流按服务端 reset 等待并暂停共享队列，其他临时错误退避，永久错误不重试。
- 有界并发独立读取，完整获取详情，不改变新增更新删除语义；不并行游标分页，不忽略读取失败。
- 私有配置与凭证不输出。验证使用模拟 HTTP，真实写入不属于本次性能测量。

## 已考虑方案
精简普通日志改动小但缺少进度；全屏 TUI 成本高；用户选择保留滚动历史的局部动态终端。展示过滤从关键字段白名单改为只忽略评分。

## 边界
业务差异模型返回数据；Reporter 接收结构化事件；ConsoleReporter 统一排序、脱敏、格式化与刷新。计算与 I/O 分开；上传管理器负责并发、通知、重试和限流；HTTP 层返回结构化错误。

## 提速
重叠独立读取、日期索引、差异只计算一次、仅必要封面上传、完成通道代替轮询、运行期间复用配置及并发安全 token、共享连接池与超时。微信读书请求总并发受限，不盲目提高详情并发。

## 验证与测量
先在旧版运行固定 30 本已有书加 1 本新增、评分及少量个人字段变化的完整模拟同步；HTTP 固定延迟，已有附件。优化后相同夹具各三次，报告中位数与请求次数；此为受控模拟，不冒充真实网络耗时。测试终端/普通模式、全字段过滤、部分失败、限流和重试、并发竞争；go test / race / vet / build。
